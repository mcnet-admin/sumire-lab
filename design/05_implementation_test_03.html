🔎 「20日締め」の意味を整理しました

当初は「毎月20日が利用料金の締め日」と想定していましたが、園の現行運用を確認した結果、 毎月20日は翌月分の予約をいったん確定するための区切りであり、利用料金の集計期間とは別であることが分かりました。

予約の区切り

毎月20日

翌月分の予約をいったん確定し、翌月の予約内容を確認するための時点です。

料金の集計期間

毎月1日 ～ 最終日

実際の利用実績と利用料金は、暦月単位で集計します。

予約の締めと、請求の締めは別のものとして扱います。
これにより、予約管理と請求管理を混同せず、それぞれの目的に合わせたデータ設計を行います。

📅 月次の集計・請求フロー

園側との確認により、通常月は次の流れで処理する方針が確定しました。

毎月1日～最終日 ① 利用実績を蓄積 実際の利用内容・利用料金を記録します。
月の最終日 ② 自動集計 その月の利用料金を園児ごとに集計します。
最終日 ③ 職員が確認 自動集計された内容を職員がチェックします。
翌月1日 ④ 請求確定 請求書を送信し、保育料引き落としの処理も同時に行います。
翌月7日 ⑤ 引き落とし 保育料とあわせて引き落とします。休日の場合は翌営業日です。
1日が休日の場合でも、請求書の送信日は1日とします。
引き落とし日までの日数が短いため、土・日・祝日であっても請求書は1日に送信する運用です。

🧪 長期休暇の取消・変更ルールを確認しました

長期休暇の予約では、園側との確認により、 利用日の7日前以降は予約料金の全額をキャンセル料とし、 利用日前日の15:30をWeb受付と翌日利用者リスト確定の境界として扱う ルールとしました。

園スタッフにとって大切な確認点
長期休暇では、7日前の料金境界と前日15:30のWeb受付・名簿確定は別のルールです。15:30を過ぎた変更・取消は園への電話連絡へ切り替える運用とします。

確認した場面と結果

確認した場面園のルールTEST結果
利用日の8日前までに取消キャンセル料なし確認済み
利用日の7日前以降に取消予約料金の全額をキャンセル料として扱う確認済み
利用日前日の15:30Web受付・翌日利用者リスト確定の境界。15:30ちょうどは受付可確認済み
利用日前日の15:31以降Web受付終了。変更・取消は園へ電話連絡確認済み
4つの境界場面すべてで、園の運用ルールどおりに判定されることを確認しました。
「7日前＝キャンセル料」と「前日15:30＝Web受付・翌日名簿確定」を別の条件として扱います。
確認方法の工夫（システム担当者向け）
実際の日付になるまで待たなくても確認できるよう、 システム上で日付と時刻を再現するTEST専用の BoundaryTest.gs を用意しました。 正常動作を確認済みの予約処理本体 ReservationWebApp.gs はそのまま残し、 TEST処理を別ファイルに分けることで、安全に繰り返し確認できる構成にしています。

※キャンセル料の請求データへの反映は、今後の利用実績・集計・請求処理の実装工程で行います。 今回は、キャンセル料発生条件と時間変更締切の境界判定を先に確立しました。

🔒 請求確定後の訂正ルールも確定しました

請求書の発行と同時に保育料引き落としの処理を行うため、 翌月1日の請求確定後に利用金額の誤りが判明しても、確定済みの請求額は書き換えません。

基本ルール

請求確定前に誤りが分かった場合は、その月の利用実績を修正して再集計します。
請求確定後に誤りが分かった場合は、差額を翌月の保育料で加算・減算して相殺します。

例：9月分で500円の過請求が後から判明した場合

9月分請求5,000円
10月1日請求確定・請求書送信
その後に判明した9月分の調整−500円

この場合、9月分の請求書を作り直して再送するのではなく、次回請求時に 「9月分調整　−500円」のように明示して相殺します。

確定済みの請求データは上書きせず、後からの訂正は「調整」として履歴を残します。

➕ 「臨時徴収」も同じ請求構造の中で扱います

園から要望のあった「臨時徴収」は、通常のすみれクラブ利用料とは別の加算項目として扱います。 また、前月分の訂正はプラス・マイナスの「調整項目」として扱います。

通常利用料4,000円
前月分調整−500円
臨時徴収＋300円
請求金額3,800円

※金額は仕組みを説明するための例です。実際の料金・臨時徴収額は園側で入力・確認します。

🧭 本番移行前に確認する操作性・アクセス環境

TEST運用の途中で、本番公開前にあらためて確認しておくべき項目が見えてきました。 ここでは、予約・集計機能そのものとは分けて、保護者が実際に使う環境と入力のしやすさに関する検討事項として整理します。

1．複数のGoogleアカウントにログインしている場合

保護者が複数のGoogleアカウントにログインしている環境でも、 Apps Script Webアプリへのアクセスや園児名簿取得が安定して動作するかを確認します。 TESTでは、通常のChromeでGoogleアカウントの切替状態により、Apps Script WebアプリのURLに /u/3/ が付加され、園児名簿を取得できない場面が確認されました。 一方、シークレットウインドウでは同じWebアプリから正常に園児名簿を取得できました。

今後の検討項目
「保護者が複数のGoogleアカウントにログインしている環境でも、Apps Script Webアプリへのアクセスや園児名簿取得が安定して動作するか。本番公開方法を含めて検証する」。

2．兄弟姉妹が在籍している家庭の連続予約

同一保護者の家庭で兄弟姉妹が同時に在籍する場合、1人目の予約完了後に最初から操作をやり直すのではなく、 続けて別の園児を予約できる導線を用意します。 予約完了後に「続けて予約する」「終了する」を選べるようにし、「続けて予約する」を選んだ場合は、 園児選択をいったん解除して予約画面へ戻す方法を基本案とします。

予約完了後の基本案：
「続けて別の園児を予約しますか？」 → ［続けて予約する］ ［終了する］

※同じ家庭の兄弟姉妹では利用日が共通する場合も多いため、日付や入力内容をどこまで引き継ぐかは、実装時に操作性を確認して決定します。
